# VNext Context And Authority Boundaries

## Role Matrix

| Role | May receive | Must not receive | Authority |
|---|---|---|---|
| Internal researcher | normalized failure, eligible historical evidence, behavior map, public measurement contract | final sealed tasks, future outcomes, hidden evaluator material | research facts only |
| External discovery worker | normalized failure, eligible retrieved evidence, frozen public-host allowlist | repository files, shell, secrets, sealed tasks, candidate arms, later outcomes | URL proposal only |
| External fetch verifier | frozen URL plan, public DNS/TLS, bounded response bytes | model context, redirects, private addresses, sealed tasks | captured source evidence only |
| Hypothesizer | frozen dossier, bounded retrieved context, allowed mutation surface | final tasks, evaluator hidden material, later outcomes | hypothesis only |
| Falsifier | frozen hypothesis, dossier, architecture facts, public measurement contract | final tasks, future results, arm labels, proposer conversation | reject/revise/test recommendation only |
| Reranker | normalized failure and deterministically eligible public memory rows | quarantined raw content, sealed tasks, prompts, credentials, future outcomes | ranking only |
| Candidate generator | accepted hypothesis, selected evidence, behavior map, mutable surface | evaluator, verifier, hidden partitions, admission code, promotion authority | candidate artifact only |
| Task agent | task-local input and one anonymous treatment capsule | research pipeline, other arms, evaluator state, hidden oracle | task output only |
| Objective verifier | raw artifacts, sealed constraints, task-local oracle | model opinions as truth | deterministic facts |
| Semantic evaluator | task specification, fixed public rubric, anonymous output, objective facts | dossier, hypothesis, lineage, proposer, prior score, arm/model identity | semantic measurement only |
| Statistical acceptor | verified task-cluster measurements, sham/control/cost facts, frozen alpha policy | raw model conversation, mutable rules | admission disposition only |
| Operator control | public evidence binding, expected revision, restrictive action | credentials in persisted receipts | stop, deny, quarantine, rollback only |

## Evaluator Isolation

Every arm evaluation uses a fresh process and state directory. Request bytes,
schema, rubric, model, reasoning effort, sampling settings, tool list, tool
policy, binary identity, stdout/result hash, and state-directory identity are
bound into the receipt. The request rejects keys or values that disclose:

- baseline, parent, candidate, treatment, or sham arm labels;
- hypothesis or research content;
- proposer identity or conversation;
- previous scores or other arm outputs;
- promotion, admission, or deployment commands.

Semantic output never decides promotion. Deterministic verification remains
authoritative for objective dimensions.

## Historical Decision Time

Evidence bank and retrieval evaluation use `availableAt`. A query at time `T`
may consume only records whose complete verifier evidence existed at or before
`T`. Later admissions, regressions, transfers, and labels cannot be projected
back into the historical candidate pool.

## External Research

External research is feature-gated and disabled for sealed evaluation. Only
allowlisted `https` primary sources may enter a dossier. Discovery runs in a
fresh Codex process with browser search enabled and shell, computer, plugins,
memory, apps, subagents, and full browser control disabled. A different
deterministic worker resolves public addresses, requires TLS, rejects redirects,
caps bytes, stores raw content, and issues a portable receipt. Each source
records URL, retrieval time, raw and excerpt hashes, title, authority class,
MIME, peer address, and bounded excerpt/fact IDs. Web content is untrusted input
and never becomes executable code.

## Trust Root

The verifier, evaluator contract, hidden benchmark partitions, statistical
policy, model identity authority, security policy, source hashes, and promotion
authority cannot be same-run mutation targets. Altering the trust root requires
a separate source change, complete tests, a new implementation hash, and a new
experiment plan.
